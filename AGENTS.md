# AGENTS.md – как развернуть борд сигналов для человека

Ты помогаешь человеку получить свой борд сигналов: каждый день он собирает самые популярные ролики TikTok и YouTube у авторов в теме человека, модель пишет короткий разбор, сайт публикуется на GitHub Pages в его аккаунте.

Говори с человеком на его языке, коротко. Ничего не публикуй и не трать его деньги без явного «да».

## Что нужно от человека

- аккаунт GitHub и установленный `gh` (если нет – помоги поставить и выполнить `gh auth login`);
- тема и язык разборов – обычно приходят готовым `signals.config.json` со страницы настройки (`site/setup.html`); списки авторов в нём пустые, их подбираешь ты;
- ключ модели: OpenRouter (`OPENROUTER_API_KEY`, https://openrouter.ai/keys) или Anthropic (`ANTHROPIC_API_KEY`). Около $0.6 в месяц. Без ключа борд работает, но без разборов и подсказок.

## Шаги

1. **Репозиторий.** Создай репозиторий из шаблона в аккаунте человека:
   `gh repo create <имя> --template ai-mindset-org/signals-board --public --clone`
   Публичный нужен для бесплатного GitHub Pages. Если человек хочет приватный – предупреди, что Pages для приватных репозиториев требует платный план GitHub.
2. **Конфиг.** Положи `signals.config.json` человека в корень. Нет готового – спроси только тему (и язык, если он не очевиден). Аудитория (`audience`) и продукт (`product`) необязательны: без них «наша версия» пишется под тему.
3. **Авторы.** Подбери сам 12–15 кандидатов: популярные аккаунты TikTok и каналы YouTube именно в этой теме, которые публикуются хотя бы раз в неделю, на обеих площадках. Проверь их
   `node scripts/collect.mjs --probe tiktok:handle1,youtube:handle2,…`
   и впиши в `tiktok` и `youtube` 8–12 тех, кто ответил `ok` и имеет ролики за последние 30 дней. Покажи человеку итоговый список одной строкой на автора; правит он, если хочет, – ждать его ответа для запуска не нужно. Если один человек ведёт и TikTok, и YouTube, укажи у обоих одинаковое поле `person`: на борде у человека будет один пост.
   TikTok часто отвечает `HTTP 429` или `503` на запросы с домашнего компьютера – это лимит частоты, а не отсутствие аккаунта. Подожди минуту и проверь этих авторов ещё раз по одному; если не проходит, впиши их по своему знанию темы: сбор в GitHub Actions обычно читает TikTok без отказов.
   Данные примера из шаблона (`site/data`) удалять не нужно: первый сбор с новой темой начинает борд с чистого листа.
4. **Ключ.** Попроси человека самому выполнить
   `gh secret set OPENROUTER_API_KEY --repo <owner>/<имя>`
   и вставить ключ в запрос команды. Ключ в чат не пиши и не проси прислать его в чат.
5. **Проверка.** `node scripts/check.mjs` должен пройти. Закоммить конфиг и отправь в `main`.
6. **Pages.** Включи GitHub Pages с источником «GitHub Actions»:
   `gh api -X POST repos/<owner>/<имя>/pages -f build_type=workflow`
   (если уже включены – `gh api -X PUT … -f build_type=workflow`).
7. **Первый сбор.** `gh workflow run signals.yml --repo <owner>/<имя>`, дождись завершения (`gh run watch`), пришли человеку адрес сайта `https://<owner>.github.io/<имя>/`.

## Как устроено

| файл | что делает |
|---|---|
| `signals.config.json` | тема, язык, окно, авторы; по желанию аудитория и продукт |
| `scripts/collect.mjs` | сбор: TikTok – публичные embed-страницы, YouTube – страница канала и ролика; ключей не нужно |
| `scripts/compose.mjs` | разбор моделью: абзац о неделе, «почему залетело», «наша версия», «о чём пост» |
| `scripts/check.mjs` | проверка конфига и данных |
| `site/` | сайт: дайджест плиткой и радаром, фильтр по площадке, страница настройки |
| `.github/workflows/signals.yml` | каждый день в 06:20 UTC: сбор → разбор → коммит → Pages |

Отбор: посты авторов за окно, по 3 лучших с площадки по просмотрам, плюс лучший пост последних суток. Один человек – один пост. Числа TikTok и YouTube не сравниваются между собой.

## Если что-то не так

- `tiktok временно придерживает запросы (overload-protect)` – TikTok ограничил частоту, следующий прогон обычно проходит;
- у YouTube число со знаком «≈» – страница ролика пришла без точных чисел, взято округлённое со страницы канала;
- пустой борд после первого прогона – авторы ничего не публиковали за окно: увеличь `window_days` или добавь авторов;
- разборов нет – проверь секрет ключа и лог шага «Разбор моделью» в Actions.
